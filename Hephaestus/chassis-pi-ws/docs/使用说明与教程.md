# Atlas 全自主运输区使用说明与教程

## 1 正式启动命令

```bash
cd ~/Atlas/chassis-pi-ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch robot_startup robot_autonomous_transport.launch.py
```

使用外部统一配置

```bash
ros2 launch robot_startup robot_autonomous_transport.launch.py \
  config:=/home/wheeltec/atlas_config/autonomous_transport.yaml
```

该 launch 按顺序启动

```text
ASRPRO USB 串口桥 + MCU 通信桥
→ 雷达和机器人描述
→ Cartographer 纯定位 + Nav2 + 导航适配后端
→ 最新 ONNX 视觉节点 + RACOM 视觉适配 + 智能分拣服务
→ 机械臂动作后端
→ 全自主运输状态机
```

## 2 开机自启

首次调试阶段先手动启动；全部设备和急停验证通过后再安装 systemd 服务

```bash
cd ~/Atlas/chassis-pi-ws
sudo ./scripts/install_atlas_autostart.sh "$PWD" wheeltec
sudo systemctl start atlas-autonomous.service
```

查看状态

```bash
systemctl status atlas-autonomous.service
journalctl -u atlas-autonomous.service -f
```

停止和取消开机自启

```bash
sudo systemctl stop atlas-autonomous.service
sudo systemctl disable atlas-autonomous.service
```

ASRPRO 本体应在 USB 供电后自动运行已烧录工程；它会周期发送 `HELLO`；Pi 串口桥完成握手后打开监听

## 3 上电后的正常等待状态

启动完成但遥控器尚未切换 AutoPi 时；状态机应处于

```text
state=WAIT_START
stage=IDLE
active=false
```

检查

```bash
ros2 topic echo /atlas/autonomous_transport/status
```

ASRPRO 应满足

```text
serial_connected=true
device_ready=true
listen_enabled=true
```

MCU 应持续发布 `/mcu/status`；状态机不会主动让 MCU 进入 AutoPi

## 4 正式比赛操作流程

1. 完成遥操作区任务
2. 把机器人驶入中转区；保证机器人本体至少二分之一进入中转区
3. 使用现有 AutoPi 遥控手势让 MCU 切换到 `AutoPi`
4. MCU 锁存自动启动状态并发布 START 事件；Pi 也会用锁存状态补偿可能丢失的单次事件
5. Pi 保持底盘制动；请求 ASRPRO 播报 `遥操作区任务已完成`
6. ASRPRO 播报语音提示；状态机等待触发词
7. 对 ASRPRO 说 `Atlas 启动`
8. ASRPRO 上报 `atlas_start`
9. Pi 请求 ASRPRO 播报 `开始执行全自主运输任务`
10. 状态机开始智能分拣；待派送取货和园区派送
11. 进入全自主模式后不再操作键盘；鼠标；手柄或遥控器；只有安全接管时才切回 Manual

## 5 完整任务顺序

```text
等待 MCU AutoPi
→ 中转区安全制动
→ ASRPRO 播报遥操作区任务已完成
→ ASRPRO 提示启动词
→ 等待 atlas_start
→ ASRPRO 播报开始全自主运输
→ 导航到智能分拣区
→ 识别齿轮与 T 型螺栓对应园区
→ 导航到待派送区
→ 识别并抓取一件货物
→ 导航到对应园区
→ 投放到当前园区槽位
→ 返回待派送区
→ 重复直到 8 件完成；目标耗尽；时间不足或无法继续安全执行
→ 播报任务结束
→ 尝试安全收臂
→ 向 MCU 上报 DONE
→ 等待恢复手势清除本轮锁存
```

## 6 运行监控

建议打开四个终端

终端一；整车日志

```bash
ros2 launch robot_startup robot_autonomous_transport.launch.py
```

终端二；任务状态

```bash
ros2 topic echo /atlas/autonomous_transport/status
```

终端三；MCU 和 ASRPRO

```bash
ros2 topic echo /mcu/status
ros2 topic echo /atlas/asrpro/status
```

终端四；后端状态

```bash
ros2 topic echo /atlas/navigation/status
ros2 topic echo /atlas/manipulation/status
```

频率检查

```bash
ros2 topic hz /mcu/status
ros2 topic hz /odom
ros2 topic hz /imu
ros2 topic hz /scan
ros2 topic hz /atlas/asrpro/status
```

## 8 恢复手势

完成任务；任务部分结束；上报失败或被安全中断后；状态机会进入 `WAIT_RESET` 或 `RECOVERY_REQUIRED`

执行现有恢复手势

```text
SWC 高
VRA 低
VRB 低
```

MCU 清除 `auto_start_latched` 后；Pi 会清理本轮任务上下文；包括园区映射；计数；异步请求；语音状态；重试计数和已失效启动事件；随后返回 `WAIT_START`

如果恢复后仍未返回 `WAIT_START`；检查

```bash
ros2 topic echo /mcu/status
ros2 topic echo /mcu/auto_task_event
```

## 9 遥控接管

任何阶段切回 Manual 时；Pi 立即执行

```text
取消导航
取消机械臂后端任务
持续发布零速度
请求 MCU 制动
停止当前全自主流程
进入 WAIT_RESET
```

接管后必须使用恢复手势清理锁存；不要直接再次触发 AutoPi

## 10 普通错误的处理方式

```text
播报超时；重试后跳过播报
智能分拣识别失败；重试后跳过派送或按明确配置使用后备映射
导航超时；重试后进入安全后继阶段
单次抓取失败；重试后跳过该货物并选择其他货物
单类连续无目标；停止选择该类别；继续检查另一类别
投放失败；保持吸盘状态；停止后续移动并按部分完成收尾
```

普通阶段错误不会永久卡死状态机
